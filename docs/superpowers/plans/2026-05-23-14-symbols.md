# Reusable cards / symbols (override-style)

**Wishlist #:** 14  **Tier:** A  **Wave:** 3  **Status:** queued
**Depends on:** Phase 0 ✓ (`siteSymbol` table, `CanvasSiteState.symbols`, `symbol-instance` ElementType)
**Blocks:** #16 multi-page nav (Wave 4)

## User-visible outcome

An Owner converts a Section (or a group of Elements) into a Symbol with a name like "Footer". The Symbol now lives at the site level. The Owner drops Instances of "Footer" onto multiple pages. Editing the Symbol master updates every Instance everywhere. On a specific page, the Owner can override a single field on one Instance (e.g. change the CTA label to "About →") without changing the master; that override survives master edits.

## Scope in

- Symbol master: a stored Section-shaped object at `site.editableState.symbols[]`.
- Symbol Instance ElementType: `{ type: 'symbol-instance', symbolId, overrides }`.
- Render-time merge: master is read by id, deep-merged with `overrides`, then rendered as a Section.
- Editor: "Convert to Symbol" command, Symbol panel listing all symbols, Instance picker.
- Override UX: editing fields on an Instance produces an entry in `overrides` keyed by inner element id; reset-to-master button.
- Symbol delete: refuses if any Instance references it; offers "Detach all instances to copies" as fallback.

## Scope out

- Symbol versioning / pinning (instances always reference current master).
- Nested symbols (a Symbol containing another Symbol Instance).
- Cross-site symbol sharing.

## Contract with neighbors

- `resolveSymbolInstance(instance, siteState): CanvasSection` — merges master + overrides.
- `RENDER_DISPATCH['symbol-instance']` calls resolve, then renders the resulting section.
- Yjs projection treats `symbols[]` as `Y.Array<Y.Map>`; instance `overrides` as `Y.Map`.

## Smoke test

- `bun run symbols:smoke`:
  - Create master "Footer" with two elements; create instance; render asserts both elements appear at instance position.
  - Edit master text; render of instance reflects change.
  - Override one inner element label on instance; render shows override; master unchanged; another instance still shows master.
  - Delete master with active instances → fails; detach all then delete succeeds.

## Acceptance criteria

- Owner converts a section to symbol, drops on 2 pages, edits master, both update.
- Per-instance override visible.
- All smokes green.

## Open questions

- Override granularity. Recommend: only element-level field overrides — adding/removing elements via override not allowed (force a new symbol if structure differs). Document and surface in editor.
