# Realtime co-editing (Yjs ops over SiteRoom)

**Wishlist #:** 4  **Tier:** S  **Wave:** 1  **Status:** queued
**Depends on:** Phase 0 ✓ (Yjs projection, SiteRoom message scaffold)
**Blocks:** none

## User-visible outcome

Two Owners with the same site open in the editor see each other's edits live — moving an Element, retyping a text run, or swapping a Style Kit appears for both within ~200ms. A small Presence Indicator shows the second Owner's name. When either closes the tab, the other continues editing alone; the site state never gets stuck or rolled back.

## Scope in

- Yjs `Y.Doc` per site held inside `SiteRoom` DO.
- WebSocket transport between editor client and SiteRoom DO (already exists for presence; extend for Yjs sync protocol).
- Y.Doc ↔ `CanvasSiteState` projection on connect (consumes Phase 0 module).
- Debounced autosave: every N edits or T seconds, persist projected `CanvasSiteState` to Postgres `site.editableState` so cold-start recovery works.
- Awareness layer for presence (cursor / selection / name colour).
- Conflict resolution = Yjs default (CRDT — last-edit-wins per field, ordered op log).

## Scope out

- Per-keystroke text-level CRDT inside `TextElement.content` (uses Y.Text). Defer to follow-up unless trivially exposed.
- Permissions / read-only sessions (every connected Owner = full editor for POC).
- Comment threads / asynchronous review.

## Contract with neighbors

- `src/live/co-edit/y-sync.ts` exports `attachYSync(doc, websocket)`.
- Autosave hook `onPersist(siteId, encodedYUpdate)` writes through to `site.editableState` as decoded JSON.
- Version history (#3) sees the latest persisted `editableState` at publish time; co-edit doesn't bypass that path.
- Awareness payload shape published in `src/live/co-edit/awareness.ts` is consumed by Presence Indicator in editor.

## Smoke test

- `bun run coedit:smoke`:
  - Spawns two simulated clients connected to one SiteRoom DO.
  - Client A inserts a Text Element. Client B receives op within 500ms and projection equals the inserted element.
  - Client B disconnects, A keeps editing; autosave fires; Postgres `site.editableState` matches A's state.
  - Reconnect simulates fresh page load; Y.Doc rebuilt from Postgres, matches.

## Acceptance criteria

- Two browser tabs editing same site show live sync.
- Tab close does not lose state.
- Presence Indicator shows both Owners.
- All smokes green.
