# RTL + per-page locale routing

**Wishlist #:** 25 **Tier:** C **Wave:** 5 **Status:** queued
**Depends on:** Phase 0 ✓
**Blocks:** none

## User-visible outcome

An Owner with pages in Arabic, Hebrew, Farsi, or Urdu sees those pages laid out right-to-left in the editor preview and on the Published Site. Visitors see correct text flow, mirrored alignments, and the page served at `/ar/<slug>` (or whatever locale prefix). The site root or `/` redirects to the default-locale page; missing locales fall back to default.

## Scope in

- `CanvasPage.locale?: string` (already in Phase 0 / #21).
- Render-time `<html lang="ar" dir="rtl">` for RTL locales (curated list: ar, fa, he, ur).
- Style Kit token: `direction: 'ltr' | 'rtl'` derived from locale; CSS uses logical properties (`padding-inline-start`, `margin-inline-end`, `text-align: start`) instead of `left`/`right`.
- Element-level position mirroring: x-coordinate of every Positioned Element transforms to `(canvasWidth - x - w)` at render time for RTL pages.
- Locale routing: published URL pattern `/[<locale>/]<slug>` — `/en/about` or just `/about` for default.
- Editor: locale selector per page; preview honours RTL.
- Site-level default locale; per-page locale optional override.

## Scope out

- Bi-di mixed runs inside one Element (rely on browser bidi algorithm).
- Vertical writing modes (Japanese / Mongolian).
- Auto-locale detection for Visitor.

- Sitemap (#22) emits per-locale URLs when multiple locales present (one `<url>` per (locale, page) pair).

## Smoke test

- `bun run i18n:smoke`:
  - Page with `locale='ar'` → render output contains `dir="rtl"` and mirrored x positions.
  - Default-locale page renders unchanged.
  - Path `/ar/about` resolves to the Arabic about page.
  - Missing locale `/de/about` returns 404 (no implicit fallback to default).
