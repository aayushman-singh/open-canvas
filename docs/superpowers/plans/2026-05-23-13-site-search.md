# Site search

**Wishlist #:** 13  **Tier:** A  **Wave:** 3  **Status:** queued
**Depends on:** Phase 0 ✓
**Blocks:** none

## User-visible outcome

A Visitor on a Published Site opens a search box (in the nav or via a `/` keyboard shortcut on supported pages) and types — matching pages and section snippets show as they type. Clicking a result jumps to that page with the matching snippet highlighted.

## Scope in

- Indexer that runs at publish time: for each page in the Published Snapshot, walk all `TextElement.content` (and any other text-bearing element types — embed titles, action labels, chart titles), build a per-site search index row keyed by site + page slug + element id, with raw text + per-element offsets.
- Storage: a `siteSearchEntry` table with `tsvector` column (Postgres FTS). One row per text-bearing element per published snapshot.
- Public search endpoint: `GET /:hostname/__rev01/search?q=<q>` returns top 10 page+snippet results.
- Public renderer optionally injects a search box element (new Section Recipe `search-box`, opt-in by Owner — not auto-added).
- On publish, replace old index rows for that site; old snapshot's index pruned.

## Scope out

- Indexing custom fonts / media filenames.
- Cross-site search.
- Search analytics / popular queries.
- Typo-tolerant fuzzy search (Postgres `pg_trgm` would do it; keep to plain FTS for POC).

## Contract with neighbors

- Index built from `PublishedSnapshot` only; not from `editableState`.
- Old entries deleted before new ones inserted in a transaction.

## Smoke test

- `bun run search:smoke`:
  - Publish fixture site; assert search entries created.
  - Query for known word returns expected page + snippet.
  - Re-publish with changed text; old text no longer hits.
  - Query escaping (`'; DROP TABLE...`) returns empty result, no SQL error.

## Acceptance criteria

- Visitor with search box can type and see live results.
- Republish updates results within seconds.
- All smokes green.
