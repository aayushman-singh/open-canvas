# Forms subsystem

**Wishlist #:** 7 **Tier:** A **Wave:** 2 **Status:** queued
**Depends on:** Phase 0 ✓ (`formSubmission` table, `FormRateLimiter` DO, Turnstile env vars)
**Blocks:** none

## User-visible outcome

An Owner adds a Form Element to a section — pick fields (name, email, message), set a submit label and success message. On the Published Site, a Visitor fills the form, a Turnstile check happens invisibly, and the submission is stored. The Owner sees submissions in a dashboard inbox. Optionally the Owner sets a webhook URL; each submission is POSTed there as JSON.

## Scope in

- New ElementType `form` with field definitions, submit label, success message, optional `webhookUrl`.
- Public renderer outputs a real HTML `<form>` posting to `/api/forms/:siteId/:formElementId`.
- Submit handler:
  - Verify Turnstile token (server-side).
  - Apply per-IP rate limit via `FormRateLimiter` DO (10/min/IP).
  - Apply per-form rate limit via DB count (100/hour/form).
  - Persist row to `formSubmission`.
  - If `webhookUrl` set, POST JSON payload (fire-and-forget but log delivery status).
- Dashboard inbox: `/dashboard/sites/:id/forms` lists forms + submissions per form, newest first.
- CSV export of one form's submissions.

## Scope out

- File upload fields (asset pipeline auth integration too thorny).
- Multi-step / conditional logic.
- SMTP email-on-submit (use webhook to Zapier / similar).
- Bot detection beyond Turnstile + rate limit.

## Schema delta

Phase 0:

```ts
// src/db/schema.ts (Phase 0)
formSubmission = pgTable('form_submission', {
  id,
  siteId,
  formElementId: text('form_element_id').notNull(),
  pageSlug: text('page_slug').notNull(),
  payload: jsonb('payload').notNull().$type<Record<string, unknown>>(),
  ipHash: text('ip_hash').notNull(),
  userAgent: text('user_agent').notNull().default(''),
  submittedAt: timestamp('submitted_at', { withTimezone: true }).notNull().defaultNow(),
});
```

## Contract with neighbors

- Form element exports its render fn so `RENDER_DISPATCH['form']` resolves.
- Submit endpoint expects `cf-turnstile-response` header or body field.
- Webhook delivery shape: `POST <webhookUrl>` with body `{ siteId, formElementId, pageSlug, payload, submittedAt }` and header `X-Rev01-Signature: <hmac-sha256>` keyed by `env.WEBHOOK_SIGNING_SECRET`.

## Smoke test

- `bun run forms:smoke`:
  - Renders fixture page with a form; asserts HTML form posts to expected endpoint.
  - Submits with stub Turnstile (always-pass); asserts row exists.
  - Submits 11 times from same ipHash; 11th rejected with 429.
  - Webhook stub receives POST and signature header.

## Acceptance criteria

- Owner creates a form, publishes, Visitor submits, dashboard inbox shows entry.
- Turnstile blocks unverified submissions.
- Webhook URL receives signed POSTs.
- All smokes green.
