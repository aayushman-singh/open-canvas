# Code block (Shiki)

**Wishlist #:** 19 **Tier:** B **Wave:** 4 **Status:** queued
**Depends on:** Phase 0 ✓ (`code` ElementType stub)
**Blocks:** none

## User-visible outcome

An Owner adds a Code Block, picks a language (TypeScript, Python, Rust, Go, JSON, Bash, etc.), pastes code, and sees syntax-highlighted output styled to match the site's Style Kit. Visitors see the same highlighted code as static HTML — no client-side JS.

## Scope in

- New ElementType `code` with `language: SupportedLang`, `source: string`, `showLineNumbers: boolean`.
- Server-side highlight at render time using Shiki (wasm-light) — generates static HTML with inline styles.
- Two theme variants: `light` (used always in POC; #20 light/dark will introduce dark variant).
- Curated language list: typescript, javascript, python, rust, go, json, bash, sql, html, css, markdown.
- Render output styled to merge with Style Kit (background colour pulled from kit, code uses kit `fontFamilyMono`).
- Snapshot publish hardcodes the highlighted HTML — no runtime tokenisation.

## Scope out

- Inline editable language selector beyond curated list.
- Diff highlighting.
- Code execution / runnable snippets.
- Per-line annotations.

## Contract with neighbors

- `highlightCode(source, language, ctx): string` returns ready-to-paste HTML.
- Bundle size: Shiki-wasm loaded lazily, cached at module scope inside the Worker isolate.
- Unsupported language falls back to plain `<pre><code>` w/ kit `fontFamilyMono`.

## Smoke test

- `bun run code:smoke`:
  - Highlight TS snippet → output contains `<span style="color: ...">` tokens.
  - Unsupported language → plain pre/code fallback.
  - `showLineNumbers: true` → output contains line gutter.

## Acceptance criteria

- Owner pastes code → editor preview shows highlight.
- Published Site shows same highlight server-rendered, no JS.
- All smokes green.
